5.weak map vs weak set
WeakMap and WeakSet are special versions of Map and Set in JavaScript that deal with memory management and object references.
They store weak references to objects
If the object is no longer used elsewhere → it gets garbage collected automatically

🔹 WeakMap
A WeakMap is like a Map, but:
Keys must be objects only
Keys are held weakly (no memory leaks)
let user = { name: "Alice" };

const weakMap = new WeakMap();
weakMap.set(user, "User data");
console.log(weakMap.get(user)); // "User data"
user = null; // remove reference

Key features of WeakMap
Keys must be objects
Not iterable (no loops like forEach)
No .size property
Used for private data / memory-safe storage

🔹 WeakSet

A WeakSet is like a Set, but:
Stores only objects (no primitives)
Objects are held weakly
let obj = { id: 1 };

const weakSet = new WeakSet();
weakSet.add(obj);
console.log(weakSet.has(obj)); // true
obj = null;
👉 Object gets garbage collected
👉 It disappears from the WeakSet

Key features of WeakSet
Only objects allowed
Not iterable
No .size
Automatically cleans up unused objects

6.explain typescript
TypeScript is a programming language developed by Microsoft that builds on JavaScript by adding types.
 It’s designed to help you write safer, more structured code—especially for large applications.

🔑 Key features
1. Static typing
You can define what kind of data a variable should hold.
let age: number = 25;
let name: string = "Alex";
If you try something wrong:
age = "twenty-five"; // ❌ Error
TypeScript catches mistakes before running the code.

2. Type inference
You don’t always need to write types—TypeScript can guess them:
let score = 100; // inferred as number

3. Interfaces & types
You can define shapes of objects:
interface User {
  name: string;
  age: number;
}
const user: User = {
  name: "Sam",
  age: 30
};

🆚 interface vs type in TypeScript
Both are used to define the shape of data, but they behave differently in some cases.

1.basic use
interface User {
  name: string;
  age: number;
}

interface User {
  name: string;
  age: number;
}
🔄 2. Extending / merging
✅ Interface supports declaration merging
interface User {
  name: string;
}
interface User {
  age: number;
}
// merged automatically
const user: User = { name: "Sam", age: 25 };

❌ Type does NOT merge
type User = { name: string };
type User = { age: number }; // ❌ Error

🧬 3. Extending
Interface (clean syntax)
interface Person {
  name: string;
}

interface Employee extends Person {
  salary: number;
}
Type (uses intersections &)
type Person = { name: string };

type Employee = Person & {
  salary: number;
};

🧠 4. Flexibility
type is more powerful
It can represent:
Unions
Tuples
Primitive aliases
type ID = string | number;
type Point = [number, number];
👉 Interfaces cannot do this.


🏗️ 5. Use cases (rule of thumb)

Use interface when:
Defining object shapes
Working with classes
You want extensibility / merging

Use type when:
You need unions (A | B)
You need complex compositions
You want aliases for primitives or tuples

8.strict non strcit mode

In JavaScript, strict mode and non-strict mode (sloppy mode) control how the code is interpreted and how errors are handled.

🧠 What is Strict Mode?
Strict mode is a way to enforce cleaner, safer JavaScript by enabling stricter parsing and error handling.

"use strict";
x = 10; // ❌ Error (not declared)
Without strict mode:
x = 10; // ✅ Works (but creates global variable — bad practice)

function show() {
  console.log(this);
}
show(); // window (or global object)

function show() {
  console.log(this);
}
show(); // window (or global object)

3. 🔐 Duplicate parameters
function sum(a, a) {
  return a;
}
"use strict";
function sum(a, a) {} // ❌ Error

🚀 Why use Strict Mode?
✅ Benefits
Catches bugs early
Prevents unsafe actions
Makes code easier to optimize by JS engines
Improves security

10.shadow dom
The Shadow DOM is a web standard designed to provide encapsulation for web components.
It allows a developer to attach a hidden, separate Document Object Model (DOM) to an element,
ensuring that the styles and structure inside that "shadow" don't leak out and affect the rest of the page—and vice versa.
//give error message ex youtube if u use lib and custom css it'll overide

Think of it like a "capsule" for your code.
eg:video comp is the custom comp built by the chrome using shadow dom
chrome doesnt show the shadow dom by default - we can enable in browser by clicking show user agent shadow dom


1. Why do we need it?
In standard HTML (the "Light DOM"), everything is global. If you write a CSS rule for button { color: red; },
 every single button on your site turns red. This becomes a nightmare for large applications or third-party widgets
(like a "Tweet" button) because:
Global CSS conflicts: Your site’s styles might break the widget.
ID collisions: Two elements might accidentally share the same ID.
Complexity: It's hard to keep track of what styles affect which components.
