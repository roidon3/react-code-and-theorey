2.How do you handle long-running tasks in React without blocking the UI?
In React, heavy computations or long-running tasks can freeze the UI because JavaScript runs on a single thread.
🔹 1. Use Web Workers (Best for heavy computations)
Run expensive logic in a separate thread so the main UI thread stays free.
This is Ideal for Data processing , Large calculations and Parsing big files
🔹 2. Memoization
useMemo is used to cache expensive calculations
useCallback is used to prevent unnecessary re-renders
🔹 3. Lazy Loading & Code Splitting
Load only what’s needed using:
- React.lazy
- Suspense
🔹 4. Break Work into Smaller Chunks
Instead of one big blocking task, split it using:
- setTimeout
- requestIdleCallback
This allows the browser to update the UI between tasks.

5. What is the purpose of Symbol in JavaScript? How is it used?
Symbol is a primitive data type introduced in ECMAScript 6 (ES6).
Its main purpose is to create unique and immutable identifiers.

const sym1 = Symbol("id");
const sym2 = Symbol("id");
console.log(sym1 === sym2); // false (always unique)
Even if two symbols have the same description ("id"), they are never equal.

🔹 Purpose of Symbol
1. ✅ Create unique object keys
Symbols help avoid name collisions in objects.
const id = Symbol("id");
const user = {
  name: "Alice",
  [id]: 123
};
console.log(user[id]); // 123
👉 This is useful when:
You don’t want keys to clash with other properties
You’re working with large apps or libraries

6. How to cancel previous API requests?
Canceling previous API requests is important in React (or any frontend app) to avoid:
Showing stale data
Wasting network resources
Race conditions (old response overriding new one)

Here are the most common and correct ways to do it:
1. Using AbortController (Recommended)

import { useEffect, useState } from "react";

function Search({ query }) {
  const [data, setData] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch(`/api/search?q=${query}`, {
      signal: controller.signal
    })
      .then(res => res.json())
      .then(setData)
      .catch(err => {
        if (err.name !== "AbortError") {
          console.error(err);
        }
      });

    return () => {
      controller.abort(); // cancel previous request
    };
  }, [query]);

  return <div>{JSON.stringify(data)}</div>;
}

2.Prevent race conditions manually
If you can’t cancel (older APIs), track the latest request:
let currentRequest = 0;

function fetchData() {
  const requestId = ++currentRequest;

  fetch("/api/data")
    .then(res => res.json())
    .then(data => {
      if (requestId === currentRequest) {
        console.log(data); // only latest response
      }
    });
}

7. How do you prevent XSS and CSRF attacks?
What are XSS and CSRF?
🧨 XSS (Cross-Site Scripting)
Attacker injects malicious JavaScript into your app
That script runs in the victim’s browser
Example - <script>alert("hacked")</script>

🧨 CSRF (Cross-Site Request Forgery)
Tricks a logged-in user into making unwanted requests
Uses their authenticated session (cookies)
👉 Example:
User is logged in → attacker triggers a hidden request like:
POST /transfer-money

🔹 How to prevent XSS
✅ 1. Avoid dangerouslySetInnerHTML
<div dangerouslySetInnerHTML={{ __html: userInput }} />
instead use this - <div>{userInput}</div>

✅ 2. Sanitize input
Use libraries like:
DOMPurify
import DOMPurify from "dompurify";
const clean = DOMPurify.sanitize(userInput);

✅ 3. Content Security Policy (CSP)
Set headers to block unsafe scripts:
Content-Security-Policy: default-src 'self';


🔹 How to prevent CSRF
✅ 1. Use CSRF tokens
Server sends a unique token
Client must send it back with requests

👉 If token is missing/invalid → request rejected

✅ 2. SameSite cookies
Set cookies like:
Set-Cookie: sessionId=abc; SameSite=Strict;

👉 Prevents cross-site requests from sending cookies

✅ 3. Use Authorization headers instead of cookies
Tokens (like JWT) in headers are safer than cookies for CSRF.

10.REST vs GraphQl APIs
In React, both REST and GraphQL are used to fetch data from servers—but they work quite differently.

🌐 1. REST API
REST (Representational State Transfer) uses multiple endpoints.
GET /users
GET /users/1
GET /users/1/posts

Multiple URLs (endpoints)
Fixed data structure (server decides response)
Can lead to:
Over-fetching (extra data)
Under-fetching (need multiple calls)

⚛️ Usage in React
Usually with:
fetch()
Axios

🔷 2. GraphQL API
GraphQL uses a single endpoint and lets the client request exactly what it needs.
📌 Key Features
Single endpoint (/graphql)
Client controls data
No over-fetching or under-fetching
Strongly typed schema

🧠 When to Use What?
👉 Use REST when:
Simple app
Standard CRUD operations
Backend already built
👉 Use GraphQL when:
Complex UI with nested data
Need optimized data fetching
Multiple clients (web + mobile)
