🔹2. What is state batching? What changed in React 18?
React groups multiple state updates together and performs a single re-render instead of multiple re-renders.
React 18 Change → Automatic Batching Everywhere
React 18 introduced automatic batching for:
timeouts , promises, async/await , native event handlers , API calls

State batching is React’s process of grouping multiple state updates into a single re-render to improve performance.
Before React 18, batching worked mainly inside React event handlers. React 18 introduced automatic batching everywhere,
including inside promises, setTimeout, async functions, and API calls.

🔹12.How to logout the application if its opened in multiple tabs
There are multiple ways to synchronize logout across tabs.
Most common approaches:
localStorage + storage event
BroadcastChannel API (modern and cleaner)

1. Using localStorage + storage Event
When logout happens in one tab:
remove token
update localStorage
other tabs listen for changes

2.Using BroadcastChannel API (Modern Approach)
const channel = new BroadcastChannel("auth");
Send Logout Message
function logout() {
  localStorage.removeItem("token");
  channel.postMessage("logout");
  window.location.href = "/login";
}
Listen in Other Tabs
useEffect(() => {
  channel.onmessage = (event) => {
    if (event.data === "logout") {
      window.location.href = "/login";
    }
  };
  return () => {
    channel.close();
  };
}, []);

🔹14.What is the difference between git merge and git rebase?
At a high level, both merge and rebase in Git are ways to integrate changes from one branch into 
another—but they do it very differently, especially in how they handle commit history.

git merge is used to combine changes from one branch into another branch.
Suppose you have:
main branch → production code
feature/login branch → login feature work
After completing the feature, you want to bring those changes into main.
Basic Flow
1. Create and switch to feature branch
git checkout -b feature/login
Make some changes and commit them.
git add .
git commit -m "Added login feature"
2. Switch back to main
git checkout main
3. Merge feature branch into main
git merge feature/login
Now Git combines the commits from feature/login into main.

git rebase is used to move or replay commits from one branch onto another branch.
Imagine:
main branch has new commits
Your feature branch is behind
You want your feature commits to appear as if they were created on top of the latest main

Important Difference: Merge vs Rebase
Merge	                      Rebase
Keeps branch history	      Rewrites history
Creates merge commit	      No merge commit
History can become messy  	Clean linear history
Safe for shared branches	  Risky on shared branches

Merge:
Keeps the full history intact (no rewriting).
Creates a merge commit (M).

15.which is better promise.all or async/await?
async/await by itself often causes sequential execution
Sequential execution increases total latency
Promise.all reduces latency by running promises concurrently
await api1(); // 2s
await api2(); // 2s
await api3(); // 2s
Total latency = 6 seconds

But with:
await Promise.all([
   api1(),
   api2(),
   api3()
]);
All requests start together.

Total latency = 2 seconds
Promise.all is better when async operations are independent because it reduces latency by executing them concurrently,
 whereas multiple await statements execute sequentially and increase total response time.
 async/await is syntax sugar over promises and is mainly for readability.
if api response depends on prevoius res use async'/await else async/await

 We use Promise.all for independent async operations to reduce latency through parallel execution.
We use async/await when operations are dependent and need sequential execution.
In real-world applications, both are commonly used together.
